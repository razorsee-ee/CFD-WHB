# Расчёт `cal` на сетке 0.1 м (Windows, blueCFD) — всё об этом кейсе

Последний большой расчёт, сделанный у пользователя на Windows/blueCFD. Цель — проверка сходимости по сетке
откалиброванной модели. **Итог: результат от сетки не зависит (0.3 / 0.2 / 0.1 м совпадают в пределах 0–2 %).**

## 1. Постановка

| | |
|---|---|
| Генератор | `model/make_case.py` (через `run_night.sh` → `model/run_coupled.sh`) |
| Сетка | ячейка 0.1 м, по ширине 23 ячейки (~0.2 м), **~1.02 млн ячеек**, `checkMesh` OK (non-ortho max 40, skewness 0.91) |
| Отложения, м²·К/Вт | газоходы **0.08**, стенки котла **0.10**, налёт на трубах **0.05** (откалиброваны по DCS на 0.3 м) |
| Губка | сценарий **A** (Гаддис + Жукаускас + излучение + налёт + α пара) |
| Режим | газ 89.2 кг/с, 750 °C от циклонов (состав с воздухом горелок, N₂ уплотнений, +14 т/ч воды; O₂ 3.0 %); пар 15.9 + 0.25 кг/с впрыска; выход 1.118 бар |
| Пыль, бункеры | 40 % от 50 т/ч в пучки; бункеры заполнены на 10 % |
| Решатель | **LTS** (`--lts --lts_co 5`, localEuler, PIMPLE maxCo 5) — стационарный SIMPLE на 0.1 м расходился на 10–15-й итерации |
| Увязка пара | 3 захода: 3000 + 1500 + 1500 итераций; температуры пара пересчитываются между заходами (50/50) |
| Ядра | 8 (MS-MPI) |

Команда запуска (Windows, MSYS2):
```bash
cd $FOAM_RUN/CFD-WHB && bash run_night.sh && VARIANTS="cal07:0.08:0.10:0.05" RES=0.07 ITERS1=4000 ITERSN=2000 bash run_night.sh
```
(`run_night.sh` по умолчанию: `VARIANTS="cal:0.08:0.10:0.05"`, `RES=0.1`, `EXTRA="--lts --lts_co 5"`.)

## 2. Как шёл расчёт

- Скорость у пользователя: **~11–12 с на итерацию** (8 ядер, i7-9700, память 2×8 ГБ DDR4 на 2133 МГц, XMP
  не включён). Для сравнения у Claude в контейнере ~5.3 с на 4 ядрах. Полный расчёт ~19–20 ч.
- Первый заход: стартовые волны давления (период ~45 итераций, размах ±13 кПа → ±1 кПа к 600-й итерации),
  доли газа через пучки качались −100…+200 % и затухали; к 600-й итерации низ газохода 730 °C, перед
  испарителем ещё ~643 °C (горячий газ не дошёл; начальное поле 650 °C). Это нормальный старт LTS.
- Заходы 1–3 досчитаны; затем запустилась цепочка `cal07` (0.07 м) и была прервана отключением
  электричества — `cal07` результатов не дал (и не мог успеть: ~35 с/итерацию).
- Предыдущая попытка (без LTS) падала на 12-й итерации во всех трёх заходах (`cal_1…3`), лог — падение
  GAMG в `correctBuoyantPressure`; причина и решение — в `docs/HANDOFF.md` §6.

**Выводы:**
1. Сходимость по сетке подтверждена: тепло, температуры, доли газа совпадают в пределах 0–2 %.
   Отличие доли через испаритель (78–81 % на грубых, 92 % на 0.1 м) — следствие толщины испарителя в одну
   ячейку на грубой сетке; его тепло одинаковое. Варианты можно считать на 0.3 м.
2. Мимо SH IIIa / II / I идёт 32–44 % газа (байпас над правым бункером), но выводы по переделкам не
   меняются: закрытие байпаса +3…7 % тепла, чистка поверхностей — десятки процентов.
3. Модель в точке термопары вертикального газохода даёт 728–734 °C против ~725 по DCS.

## 4. Где лежит у пользователя (Windows)

`$FOAM_RUN/cal_1`, `cal_2`, `cal_3` (`$FOAM_RUN` = `/home/ofuser/blueCFD/ofuser-of12/run`);
в `cal_3`: `summary.txt`, `summary.json`, `views.html`, `views_*.png`, `monitor.png`, последнее время в
`processor*/1500` (и собранное `1500/` после `reconstructPar -latestTime`). ~8–10 ГБ.

## 5. ParaView (Windows/blueCFD)

```bash
cd $FOAM_RUN/cal_3 && paraFoam -builtin
```
Properties → Case Type: **Reconstructed Case** (если делали `reconstructPar`) или Decomposed Case → Apply →
Last Frame → Filters → Slice (Y Normal, Origin 0 0 0, снять Show Plane) → раскраска T (K; 723–1033 = 450–760 °C),
U (0–15), p_rgh (давление без гидростатики) → вид −Y → Reset Camera.

(OpenFOAM-12, `foamRun`, модуль `fluid`).
