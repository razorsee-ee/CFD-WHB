# CFD-Venturi — правила для Claude

Скруббер Вентури на установке пиролиза: где масло попадает на стенку и где возможен кокс
(на практике отложения всегда в горловине). Расчёты в OpenFOAM (Foundation).

## Сначала прочитать
1. `docs/HANDOFF.md` — полная передача проекта, затем `docs/STATUS.md`. Рабочая ветка **`claude/hopeful-noether-1zya1a`**.
2. По кейсу — `<кейс>/README.md`. ParaView для пользователя — `docs/paraview_guide.md`.
3. Общее для новых проектов и переход на Linux — `docs/NEW_PROJECT_OPENFOAM.md` здесь и `docs/LINUX_OF14.md` в `razorsee-ee/CFD-WHB`.

## Версии (решение 21.11.2026)
- Существующие кейсы — **OpenFOAM-12**, считаются у пользователя на **Windows, blueCFD-Core 2024** (MSYS2). Их не ломать.
- На новой системе пользователя (Ubuntu 26.04) стоит **OpenFOAM-14**. Перенос кейса на 14 — отдельной копией/веткой,
  синтаксис сверять с `$FOAM_TUTORIALS` версии 14; переносить, только когда пользователь попросит.

## Где ты работаешь — определить в начале
- **Ubuntu у пользователя** (Claude Code / Claude Desktop на его ПК, i7-9700, 8 ядер): `source /opt/openfoam14/etc/bashrc`;
  длинные расчёты — в `tmux`; `sudo` и всё вне папки проекта — только с согласия.
- **Облачный контейнер Claude**: OpenFOAM-12 — `tools/setup_openfoam12.sh` (или `tools/setup_cloud_env.sh`), 4 ядра.
- **Windows/blueCFD** — пользователь сам; ему готовые команды для MSYS2, грабли Windows — в `docs/HANDOFF.md`.

## Пользователь
- По-русски, коротко. Инженер-практик; физическая правдоподобность важнее красивой картинки.
- Команды — каждая в отдельном блоке `bash`. Что не проверено — так и сказать.
- Сначала проверять самому на грубой сетке. «Пока ничего не считай» — только рассуждать. Беречь токены: логи `tail`/файлом.

## Git
- После каждого законченного шага — коммит и пуш в рабочую ветку; результаты расчётов не коммитить.
- В конце работы обновить «где остановились» в `docs/HANDOFF.md` / `docs/STATUS.md`.
- Во время идущего расчёта не делать `git checkout -- .`.
