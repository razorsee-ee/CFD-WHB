# CFD-WHB — правила для Claude

Котёл-утилизатор (WHB) за CFB-топкой, расчёты в OpenFOAM (Foundation).

## Сначала прочитать
1. `docs/HANDOFF.md` — полная передача проекта: пользователь, объект, данные DCS, модель, калибровка, где остановились.
   Рабочая ветка — **`claude/compassionate-rubin-t8h1bo`** (с 21.11.2026 в неё влиты заметки по Linux/OF-14).
   Разделы HANDOFF про Windows/blueCFD/MSYS2 и контейнер с OF-12 (§0, §2) — история; среда сейчас описана ниже.
2. `docs/LINUX_OF14.md` — решение 21.11.2026: Linux + OpenFOAM-14, отличия синтаксиса 12 → 14.
3. По мере надобности: `docs/MODEL_SETUP.md`, `docs/CALIBRATION.md`, `docs/NEW_PROJECT_OPENFOAM.md`.

## Где ты работаешь — определить в начале
- **Ubuntu 26.04 у пользователя** (Claude Desktop, вкладка Code, папка `~/OpenFOAM/run/CFD-WHB`): i7-9700, 8 ядер
  без HT, 16 ГБ → `numberOfSubdomains 8`. Установлено и проверено 21.11.2026:
  - OpenFOAM-14 (пакет `openfoam14` 20261008), подключается в `~/.bashrc` (с `HWLOC_COMPONENTS=-gl` — нужно на 26.04).
    В неинтерактивном bash Claude: `export HWLOC_COMPONENTS=-gl; . /opt/openfoam14/etc/bashrc` в начале команды.
    Тест `multiphaseEuler/fluidisedBed` до 0.05 с на 8 ядрах — 3 с, без ошибок. ParaView, gnuplot, gmsh, tmux есть.
  - Python 3.14: системные numpy/scipy/pandas/matplotlib/vtk; venv **`~/venvs/cfd`** (видит системные пакеты) —
    CoolProp, jupyterlab, pythonnet, PyFoam, fluidfoam; Jupyter-ядро «Python (cfd)». Скрипты проекта — `~/venvs/cfd/bin/python`.
  - DWSIM 9.0.5 (`/usr/local/lib/dwsim`, .NET 8); из Python — пример `~/venvs/cfd/dwsim_example.py`.
  - `$FOAM_RUN` = `~/OpenFOAM/ed-14/run` (по bashrc OpenFOAM); проект лежит в `~/OpenFOAM/run/CFD-WHB`, расчёты —
    в `$FOAM_RUN/<кейс>` или в папке проекта (результаты в `.gitignore`).
  - Команды запускаешь сам; длинные расчёты — в `tmux` (`tmux new -d -s <имя> '...'`), не блокируя сессию;
    остановить решатель — `pkill -x foamRun`. `sudo` из сессии не работает (нужен пароль): установку пакетов
    и всё вне папки проекта — только с согласия, команду давать пользователю отдельным блоком, он выполнит сам.
- **Облачный контейнер Claude** (окружение «CFD-WHB»): OpenFOAM-14 ставится setup script'ом → `source /opt/of14env.sh`.
  Если файла нет — `bash tools/setup_openfoam14.sh` (готовый пакет, ~30 с; из исходников не собирать). 4 ядра.
- **Windows/blueCFD (OpenFOAM-12)** — только старые кейсы; это делает сам пользователь в MSYS2, ему нужны готовые команды.

## Версии
- Новое и переписываемое — **под OpenFOAM-14**. Синтаксис сверять с `$FOAM_TUTORIALS` версии 14, а не по памяти.
- Кейсы на OpenFOAM-12 (blueCFD) не ломать: при переносе делать новый кейс/генератор рядом, пока 14 не даст
  тот же ответ, что откалиброванная 12 (газ ~618 °C на выходе, пар ~441 °C, сетка 0.3 м).

## Пользователь
- По-русски, коротко. Инженер-практик, знает установку лучше модели; физическая правдоподобность важнее картинки.
- Команды для терминала — каждая в отдельном блоке `bash`. Что не проверено — так и сказать.
- Сначала проверять самому на грубой сетке, потом давать ему. «Пока ничего не считай» — только рассуждать.
- Беречь токены: длинные логи — `tail`/файлом.
- Код и комментарии в коде — по-английски; документы в `docs/` — по-русски.

## Git
- После каждого законченного шага — коммит и пуш **только в рабочую ветку `claude/...`**. Результаты расчётов
  не коммитить (см. `.gitignore`), только сводки и эталонные картинки в `docs/`.
- Без явного слова пользователя: не пушить в `main`, не делать `git push --force`, не удалять и не переписывать ветки
  (`reset --hard` на запушенное, `rebase` опубликованного).
- В конце работы дописать итог в `docs/HANDOFF.md` («где остановились»): следующий чат (облако или ПК) начнёт с него.
- Во время идущего расчёта не делать `git checkout -- .`: собьёт `controlDict`.
